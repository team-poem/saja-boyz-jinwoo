# 흉흉 안내 문구와 위치 재시도 경험 개선

## 기준과 목적
- PR37이 머지된 최신 dev `c108cee`에서 시작한다. 사용자 첨부는 위치 timeout 안내의 행동 부재와 단조로운 상태 표현을 보여준다.
- 지도 위치 오류에서 즉시 재시도하고, 지도·검색·목록·상세·제보·404의 사용자 상태 안내를 흉흉의 색감과 말투로 정돈한다. 지도 위 `지역 좌표: 기상청` 링크와 `기사 위치 보기` 버튼은 제거한다.
- 사건 사고를 가볍게 다루는 농담·공포 유도·위험도 추정·안전 단정·근거 없는 복구 예정 약속은 쓰지 않는다. 기사 원문/제목/날짜, 검증/접수/권한 사실과 오류 구분은 바꾸지 않는다.

## 위치 오류와 직접 재시도
- 현재 상태 안내에 제목 `위치를 한 번 더 확인할까요?`, 오류별 도움말, 명시적 `위치 다시 시도` 버튼을 둔다. 접근 가능한 이름도 `위치 다시 시도`다.
- timeout 도움말: `위치 확인 시간이 초과됐어요. 한 번 더 확인해 볼까요?`
- 권한 거부 도움말: `위치 권한이 꺼져 있어요. 브라우저 설정에서 허용하면 내 주변부터 볼 수 있어요.`
- 미지원 도움말: `이 브라우저는 위치 확인을 지원하지 않아요. 지도에서 원하는 동네를 살펴보세요.`
- 조회 실패/비정상 좌표 도움말: `내 위치를 확인하지 못했어요. 연결 상태를 확인한 뒤 다시 눌러주세요.`
- 버튼은 기존 수동 locate 경로를 호출한다. SDK/페이지 재로드 없이 현재 지도·기사·필터·뷰포트를 유지하고, 응답이 유효하면 내 위치로 이동한다. 성공하면 오류 카드가 사라진다.
- SDK 준비 전이나 위치 조회 중에는 재시도 요청을 추가로 보내지 않는다. 빠른 연속 클릭도 요청1개만 만든다. 기존 위치 버튼의 pending/spinner·수동 재조회·10초 timeout·좌표 검증·StrictMode 첫 요청 중복 방지·복귀 위치·SDK 오류 및 늦은 callback 안전성을 유지한다.
- 권한 거부를 숨기거나 OS 권한 창을 강제로 다시 띄우지 않는다. 거부 시 설정 안내를 제공하고 지도 탐색은 가능해야 한다. 위치 영구 저장·watchPosition·새 위치 API는 추가하지 않는다.

## 지도 오버레이 정리
- 지도 위 출처 링크와 전체 기사 위치로 이동하는 버튼을 모든 데이터 상태에서 제거한다. 숨김 처리나 모바일에서만 제거하는 방식은 사용하지 않는다.
- 해당 버튼 전용 fitArticles ref/콜백과 불필요해진 SDK 타입만 함께 제거한다. 마커 그룹화·선택·상세 시트·현재 위치·뷰포트 보존은 유지한다. 기사 좌표로 자동 fit/zoom하지 않는다.
- 좌표 출처는 서비스 안내 `/about`에 `기상청 지역 대표 좌표` 링크(`https://www.data.go.kr/data/15084084/openapi.do`)로 정리한다. 지도 상세 시트의 대표 위치/정확한 현장과 다를 수 있다는 설명은 유지한다.

## 전반적인 상태 안내
- 기존 Tailwind 토큰을 쓰는 작은 공통 안내 표면을 필요한 상태에 적용한다. 서버/클라이언트에서 쓸 수 있는 단순한 표현 컴포넌트로 충분하며 전역 상태·메시지 프레임워크·의존성을 추가하지 않는다.
- 흰 표면, 얇은 브랜드 색 테두리/옅은 배경, 작은 관측/안내 SVG 아이콘, 제목·설명·행동의 시각적 위계를 사용한다. 거대한 빨간 배경·경고 이모지 반복·과도한 효과는 사용하지 않는다.
- 기본 간격은 기존 디자인 토큰에 맞춰 안쪽16px, 요소 사이8~12px, 제목14~16px의 굵은 글자, 본문13~14px/읽기 편한 줄높이, 버튼 최소44px 터치 영역을 기준으로 한다. 좁은 화면에서 줄바꿈·행동 버튼을 보장한다.
- 지도의 여러 안내는 기존 세로 스택을 유지해 헤더/필터/하단 카드/내비게이션과 겹치지 않아야 한다. 오류가 지도 전체 클릭을 가로막지 않는다.
- 상태 메시지는 사용자에게 다음 행동을 알려준다. 이미 구체적인 `기사를 불러오지 못했어요`, `검색 결과가 없어요`, `접수 여부를 확인하지 못했어요` 등은 사유/상태 본문으로 유지하고, 상황에 맞는 제목·도움말·행동과 표현을 보완한다. 테스트를 맞추기 위해 옛 문구를 숨겨 두거나 중복 출력하지 않는다.
- 실제 제보 접수 성공만 성공으로 표현한다. 불확실 응답·입력·첨부·재시도 키·기존 Suspensive 경계는 그대로 유지한다. 입력 검증과 사진/기사 원문·출처 표시도 정확성을 우선한다.
- 로딩은 기존 스켈레톤·스피너와 접근성 라벨을 유지한다. 눈에 보이는 장황한 로딩 문장을 다시 도입하지 않는다. 역할(alert/status), focus, aria-busy, disabled, 기존 retry/reset 동작을 유지한다.
- 문구·적용 화면은 `copy-audit.md`에 적는다. 지도·검색·목록·상세·아카이브·최근 검색·제보·전역 오류·404를 브라우저에서 대표 상태로 확인한다. 정적인 기사 내용이나 화면 구조 전체 재설계는 범위 밖이다.
