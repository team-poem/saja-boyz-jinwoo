## 이번 기능의 범위

1. 지도 단일 기사·하단 기사 카드·목록·검색의 기사 진입을 공통 상세 시트로 통합한다. 현재 목록 본문이나 검색 디자인을 별도로 재설계하지 않는다.
2. 지도는 기본 높이로 열고 펼칠 수 있게 한다. 목록·검색에서는 배경과 읽던 위치를 보존하며 충분한 내용을 읽을 수 있는 확장 상태로 진입하는 것을 제안한다. 직접 공유 유입도 확장 상태로 표시한다.
3. 닫기·Escape·브라우저 뒤로가기는 앱 내부 진입 위치로 복귀하고 앞으로가기로 다시 열 수 있게 한다. 외부 직접 유입에서 닫기는 앱의 기본 지도/목록으로 안전하게 이동하며 무조건 외부 히스토리로 되돌리지 않는다.
4. 지도 숫자 원의 여러 기사를 잃지 않는다. 지역 기사 선택 상태에서 단건 상세로 들어가고 돌아올 수 있게 하며 기존 선택 패널과 새 상세 패널을 동시에 노출하지 않는다.
5. 시트 안의 스크롤과 드래그가 배경 지도/문서로 전달되지 않게 한다. 포커스 진입·복구, 키보드 조작, 동작 줄이기 설정을 지원하고 작은 화면에서도 공유 버튼까지 접근 가능하게 한다.
6. 이미지 실패·공유 취소·공유 미지원 복사·복사 실패·API 오류 재시도와 없는 기사 안내를 유지한다. 원문은 검증된 주소로 새 탭에서 연다.

## 데이터가 디자인과 다른 부분

- 시안의 소방/교통 분류·진행 상태·정확 주소·조회수·언론사 로고를 고정 샘플로 채우지 않는다.
- 상세 API에는 위치가 없다. 지도에서 검증한 위치 데이터가 있는 경우만 사용하며 대표 좌표를 정확한 현장 주소처럼 표시하지 않는다.
- 원문 도메인을 실제 언론사명이나 로고로 단정하지 않는다. 검증된 원문 링크와 확인 가능한 출처 표현을 사용한다.
- 주변 기사 영역은 실제 위치 근거와 정렬 기준이 있어야 한다. 지역 대표점으로만 묶인 기사는 '같은 지역 보도'로 구분하고, 관련 근거가 없으면 구역을 숨긴다. 기사3개를 사건3건으로 단정하지 않는다.
- 미정인 필터 재정의·인기순 집계·전체 목록 재설계·제보·브랜드·새 PC 레이아웃은 이번 기능에 섞지 않는다.

## 공유 URL과 검색 유입

- `/incidents/{id}`를 단일 대표 주소로 유지한다. 지도·목록·검색·아카이브에는 실제 href를 가진 링크를 유지한다.
- 내부 이동은 Next 병렬/가로채기 라우트로 배경 위에 공통 상세를 띄우는 방향을 우선 검증한다. 직접 유입·새로고침은 같은 기사의 확장 시트 외형과 본문을 서버 렌더링한다.
- 본문을 useEffect 후 포털에서만 생성하지 않는다. 제목 h1, 실제 요약, 기사 발행 시각, 검증된 원문 출처는 JS·지도 SDK·위치 권한 없이 초기 HTML에 있어야 한다.
- 시트의 공통 본문/조회/메타데이터를 재사용해 제목·description·canonical·OG/Twitter·공유 주소가 같은 기사를 가리키게 한다. 복귀용 쿼리가 대표 주소를 중복시키지 않게 한다.
- 검색 화면의 noindex·canonical·제목이 상세 시트에 남지 않는지 검사한다. 시트를 다른 화면에서 닫았을 때 병렬 슬롯도 해제한다.
- 기사별 공유 카드에 실제 제목·발행 정보·브랜드를 표시하는 개선은 한국어 렌더링·로컬 폰트·응답 검증이 가능한 범위에서 검토한다. AI 이미지를 실제 현장 사진처럼 대표 이미지로 사용하지 않는다.
- 현재 집계/요약 서비스 역할에 맞는 WebPage+citation을 유지하고 확인된 본문과 일치시킨다. 자체 취재를 뜻하는 저자·언론사·보도일을 만들어 NewsArticle 속성을 채우지 않는다.
- 존재하지 않는 기사의 실제404와 오류 페이지 noindex를 실측한다. 기존 로딩/스트리밍 경계가 상태코드에 미치는 영향을 확인하고 통신 장애를 없는 기사로 바꾸지 않는다.
- 기존 sitemap과 서버 아카이브의 과거 기사 발견 경로를 유지한다. 조회수 API·전체 sitemap 수집 API·임의 SEO 키워드 본문 생성은 별도 기능이다.
- 검색 순위 상승은 보장할 수 없다. 이번 목표는 상세 URL 발견·실제 본문 색인·공유 미리보기·출처 신뢰 정보를 올바르게 유지/개선하는 것이다.
