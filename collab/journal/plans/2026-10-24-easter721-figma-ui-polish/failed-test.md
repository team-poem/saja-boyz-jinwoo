# 시나리오

1. 실제 프로덕션 NextLink 상세 이동이 단 한 번 API를 조회하며, 응답 없는 API는 실제 5초 타임아웃 한 번으로 복구 안내에 도달한다. 직접 HTML 조회와 없는 기사 404는 유지한다.
2. 지역 12건 선택 시트에서 확장하고 10번째 기사까지 스크롤한 뒤 상세를 열고 닫으면 확장·스크롤·원래 링크 포커스가 보존된다.
3. 최신 Figma 대조로 공통 간격·타이포·불필요한 레이어를 수정하고 실제 브라우저에서 지도·목록·검색·제보·상세 및 작은 화면을 확인한다.

4. 검색 결과에서는 추천 영역을 반복하지 않는다. 빈 검색에서 추천 클릭 시 44px 검색 버튼 접근과 스피너를 유지하고 칩의 너비/높이는 변하지 않는다.
5. 최근 카드4개만 표시해도 모든 기사로 지도 원을 집계한다. 기간 필터·지도 중심·마커 수명주기는 유지한다.

## 학습

실제 production NextLink의 RSC 헤더는 pinned Next의 기본 정규화로 지워졌으며 단순 헤더 unit fixture만으로 탐지되지 않았다. 실제 production 회귀로 고정했다. 지역 선택은 숨긴 DOM을 유지해야 스크롤과 링크 포커스를 보존할 수 있다. 홈 데이터 전달 계약은 기존 page 구조를 유지하고 시각 요소가 없는 JSON-LD 컴포넌트로 보존했다.

6. 320×568 제보에서 페이지 끝까지 스크롤한 뒤 제목을 focus해도 입력 전체가 고정 헤더와 하단 버튼 사이에 보인다. 실제 production 디자인 감사에서 y0~41로 헤더에 가려지는 RED를 관찰했다. CSS scroll-margin 80/112에 safe-area를 더해 복구하고 같은 브라우저 회귀를 재실행한다.

7. 작은 제보 화면에서 키보드 Tab으로 첨부 삭제 버튼에 도달해도 버튼 전체와 포커스 표시가 고정 하단 버튼 위에 보인다. 후보2의 실제 Tab에서 y537~571 중11px만 보이는 RED를 확인했다. 동일 form 버튼에도 스크롤 여백을 적용하며, 브라우저 임시CSS46개 포커스 기록에서 해결을 확인한 뒤 실제 빌드에서 재검증한다.
