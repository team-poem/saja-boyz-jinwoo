# 전체 화면 디자인 재구축 계획

확인일: 2026-10-14 · Figma 개인 계정 easter721@gmail.com · dev 기준 fc9b0af.

## 요청 범위

링크의 `45:3421`은 파일 진입점이다. 그 노드 하나를 최종 시안으로 지정한 요청이 아니다. 지도뿐 아니라 검색, 검색 결과, 목록, 기사 상세, 제보, 선택 시트, 공유 및 공통 요소를 전체적으로 다시 맞춘다. 크기·여백·폰트·색·아이콘·그림자·레이어·스크롤·선택 상태를 함께 다룬다.

사용자가 별도로 지정한 변경은 두 가지다. 지도는 지역 대표 고정 좌표마다 기사의 개수를 나타내는 원을 표시하고 개수가 많을수록 커진다. 브랜드는 흉흉으로 통일하고 서비스에 맞는 독자 SVG 로고를 만든다.

이번 브랜치는 분석·계획과 로고 제안만 공유한다. 제품 코드·기존 테스트·의존성은 변경하지 않는다. 실제 구현은 후속 sobaya 명세·정확한 테스트 초안·승인·루프·gate·review를 거친다.

## 확인한 근거

- [Figma 전체 파일](https://www.figma.com/design/TCSILMzViAVqeHRphoyHCH?node-id=0-1)의 페이지 구조를 조회했다. 초기 402px 어두운 시안, 393px 밝은 제품 화면, 별도 사회·안보 시안이 공존한다.
- 아래 12개 프레임의 디자인 컨텍스트와 렌더를 확인했다. 같은 이름의 상세 두 프레임과 공유 시안도 비교했다. 오래된 어두운 시안의 전체 필터는 흐름 참고로 조회했다.
- 최신 dev의 실제 라우트 및 렌더 경로를 읽었다. 예전 `IncidentList`와 운영 `ArticleList`가 다르므로, 예전 컴포넌트를 예쁘게 바꿔도 운영 화면에 반영되지 않는 문제를 구분했다.
- 공개 사이트 https://hyunghyung.vercel.app 에서 393×852 지도·목록·검색·검색 결과·제보·상세, 1440×900 목록을 읽기 전용으로 촬영했다. 공개 배포의 정확한 SHA는 확인하지 않았으므로 이 촬영을 dev 빌드의 검증으로 주장하지 않는다. HTML 구조와 최신 dev 소스에서 공통적으로 관찰되는 차이를 근거로 삼았다. 제보 제출은 하지 않았다.
- [운영 OpenAPI](https://poem-news.168.107.37.12.sslip.io/openapi.json)와 `/map/articles?offset=0&limit=100`을 조회했다. 확인 순간 기사 44개 중 위치 resolved 1개, unresolved 43개이며 resolved는 울산광역시의 region 대표점이다. 운영 표본 하나로 여러 지역·다수 기사 원의 시각 품질을 검증할 수는 없다.

## 왜 비슷해 보이지만 계속 다른가

1. **색과 일부 수치만 가져오고 화면 구성은 별도로 만들었다.** AppShell은 지도 외 모든 화면에 같은 외곽 여백과 흉흉 헤더·하단 메뉴를 넣는다. Figma의 상세·제보는 각각 전용 화면이다. 제보에 헤더가 두 번 나오고 첨부 영역 위로 메뉴가 겹치는 것은 이 구조에서 발생한다.
2. **폰트 선언과 로드는 다르다.** globals.css는 Pretendard·Inter 이름만 선언한다. @font-face 및 next/font 로드가 없고 공개 브라우저 FontFaceSet에도 Pretendard가 없다. 실제 폴백으로 글자 폭·굵기·줄바꿈이 바뀐다. Figma는 Inter, Pretendard가 혼재하고 별도 시안에는 JetBrains Mono도 있다. 글자마다 생성 도구가 적은 이름을 그대로 복사하는 방식 대신 실제 한글 폰트와 숫자 폰트를 정하고 로드해야 한다.
3. **예전 디자인용 사건 컴포넌트와 실제 기사 UI가 분리돼 있다.** 운영 카드에는 배지·위치 대신 기사 발행일·원문 링크가 들어간다. 데이터 계약 차이와 레이아웃 차이가 섞여 있다. 분류·상태를 임의로 채워 같아 보이게 만드는 방법은 쓰지 않는다.
4. **Figma에도 다른 시안·브랜드·상태가 공존한다.** 흉흉·위험추적·가제, 단일 점·큰 숫자 원, 다른 내비게이션과 폰트가 있다. 이전 인덱스의 노드가 잘못됐다고 단정할 수는 없지만 최종 화면별 기준과 예외가 고정돼 있지 않다. `docs/ui-contract.md`에도 이미 없는 경로와 목표 계약이 남아 있다.
5. **지도 화면의 주요 UI가 아직 빠져 있다.** 현재 지도는 헤더·기사 위치 안내·내 위치·선택 시트까지만 제공한다. 필터 행, 가로 기사 카드, 메뉴 아이콘과 활성 상태를 갖춘 완성 구성이 아니다. 1건은 24px SVG 점, 2건 이상은 숫자 원으로 나뉜다.
6. **화면별 시각 검증이 완료 기준으로 묶이지 않았다.** 기존 행동 테스트와 CI 통과만으로 Figma 일치를 보장할 수 없다. 이미지 유무, 긴 제목, 키보드, 짧은 가로 화면, 시트 선택 상태까지 같은 기준으로 비교해야 한다.

## 공통 디자인 수치와 구조

밝은 주요 제품 시안에서 읽은 값: 좌우 16px, 검색 헤더 radius 16px와 내부 좌우 16px/세로 10px, 카드 radius 14px, 가로 카드 너비 200px/간격 10px, 목록 이미지 80×80px와 radius 8px, 하단 메뉴 높이 68px/radius 28px, 제보 원형 액션 54px, 상세 이미지 361×190px, 제보 버튼 높이 52px. 별도 45:3421의 메뉴 73.4px·제보 50px와는 다르다. 둘을 같은 수치라고 기록하지 않는다.

Pretendard 한글 폰트와 Inter 숫자·라틴 폰트를 실제 로컬 파일로 로드하고, 굵기별 파일 또는 가변축을 확인한다. Figma 한글이 Inter로 표기된 부분은 실제 한글 폴백을 포함해 렌더를 대조한다. 로고는 텍스트 폰트에 의존하지 않는 SVG path로 만든다. Tailwind는 유지하고 전역 Preflight를 켜는 대규모 부수 변경은 하지 않는다. 화면에서 필요한 기본 margin·line-height·버튼 border를 명시한다.

공통 부분은 로고, 검색 헤더, 필터 행/메뉴, 내비게이션, 배지, 기본 액션으로 한정한다. 지도 가로 카드·목록 카드·검색 결과 카드는 실제 쓰임에 따라 별도 UI를 둔다. 기존 `features/<기능>/ui/<컴포넌트>/` 규칙을 따라 컴포넌트 폴더 안에 관련 UI와 필요한 행동 테스트를 함께 둔다. 제보 요청 상태는 부모에 유지하고 시각 영역만 분리하여 입력·첨부·재시도 키가 사라지지 않게 한다.

## 지역 고정 좌표의 개수 원

- 서버의 `precision: region` 대표점을 중심으로 지역마다 하나의 원을 그린다. 위치를 줌이나 화면 픽셀 거리로 묶지 않는다. 지도 배율이 바뀌어도 같은 지역은 같은 그룹이다.
- 숫자는 해당 지역의 **중복 제거된 기사 수**다. 동일 사건의 서로 다른 기사를 하나의 사건으로 합칠 근거는 현재 없다. 미확정 위치 기사는 임의 좌표에 표시하지 않고 개수 범위를 설명한다.
- 현재 구현은 위도·경도의 문자열이 같은 항목을 묶는다. 운영 API는 고정 지역 대표점과 label을 제공하지만 `region_id`는 없다. 구현 전 지역 단위(시·도인지 시·군·구인지), 표준 label·대표점의 안정성을 서버 카탈로그 기준으로 고정한다. 우선 현재 region 응답의 표준 label과 대표점 조합으로 키를 구성하고, 별칭이 가능한 계약이면 `region_id` 제공이 필요하다. 프런트에서 새 지역 좌표표나 임의 역지오코딩을 만들지 않는다. 기존 address/neighborhood 결과를 같은 지역이라고 추측해 합치지도 않는다.
- **1건도 숫자가 있는 지역 원으로 표시**한다. 현재의 1건 SVG 점과 다건 원의 이원화를 없앤다. 단일 지역 원의 최소 지름 32px는 이번 새 요구를 위한 제안이며 Figma에 있는 값이라고 주장하지 않는다.
- 기존 숫자 원의 Figma 관찰값은 5→38.4px, 7→48px, 12→72px다. 최초 구현 제안은 1→32px, 2~5→38.4px, 6~9→48px, 10 이상→72px의 단계형이다. 큰 수는 72px로 상한을 두어 지도가 가려지지 않게 한다. 각 숫자가 늘 때마다 커지는 연속식이 필요하면 승인 명세에서 식을 정하고 동일 구간 사진으로 다시 비교한다. 이 구간들은 시안에 명시된 집계 규칙이 아니라 구현 제안이다.
- 빨강 60% 표면·흰 테두리·숫자 중앙 배치와 선택 링을 공통으로 유지한다. 지원하지 않는 사건 상태를 빨강/주황/초록으로 임의 분류하지 않는다. 작게 보이는 원도 최소 44px의 조작 영역을 제공한다.
- 선택하면 지역 이름·기사 개수·해당 지역의 전체 기사 목록을 시트에서 보여준다. Escape·닫기·선택 해제·포커스 복귀·짧은 화면 내부 스크롤을 유지한다.
- 서울 기본 중심·탭 내 뷰포트 복원·명시적 내 위치 권한 요청은 유지한다. 전체 지역 보기 버튼은 기존 기사 위치 보기 기능을 헤더/지도 액션 위치에 맞춰 재배치한다. 원을 만들었다는 이유로 처음 접속할 때 자동 이동하지 않는다.

## 흉흉 SVG 로고 제안

이 폴더의 `brand-proposal.svg`는 **지역 관측 원 + 중심 빨강 신호 + 기하학적으로 그린 흉흉 글자**로 만든 초안이다. 지도에서 흩어진 뉴스를 지역 신호로 읽는 서비스와 연결한다. 해골·혈흔 같은 장식 없이 Figma의 #e8192c와 #0f172a를 사용한다. 한글도 path로 만들어 폰트가 없는 기기에서 바뀌지 않는다. `brand-preview.html`에서 작은 헤더 크기·어두운 표면·기호 단독 사용을 확인할 수 있다.

이 SVG는 디자인 산출물이다. 아직 `public/`이나 제품 헤더·favicon에 적용하지 않았다. 실제 적용 때 원본 viewBox를 유지한 가로형과 기호 단독형을 제공하고, 이미지 대체 텍스트와 홈 링크 이름을 흉흉으로 맞춘다.

## 구현 순서와 PR 범위

1. **공통 기반 + 모든 라우트의 화면 틀**: 실제 폰트, 디자인 토큰, SVG 로고, 헤더·메뉴·필터 표면, 지도/검색/목록/상세/제보의 화면별 shell. 전용 화면에서 이중 헤더·메뉴·여백을 제거한다. 공용 변경을 먼저 머지해 다른 기능 PR이 따로 다른 스타일을 만들지 않게 한다.
2. **지도 전체 구성 + 지역 원 + 선택 시트**: 고정 지역 집계, 1건 포함 숫자 원, 선택 상태, 내 위치, 가로 최신 기사 카드, 모든 지역 보기 액션, 필터 표면, 시트. SDK 로드·인증 실패 안내도 같은 시각 언어로 정리한다.
3. **검색·목록·상세·제보의 전체 UI 마감**: 화면별 카드·이미지·정보 순서·공유·폼·첨부·제출 액션과 로딩/빈 결과/오류/재시도 상태를 맞춘다. 화면이 많으면 이 단계를 두 PR로 나누되 완료 범위를 생략하지 않는다.

각 PR은 dev에서 분기해 dev로 올린다. main 통합은 별도 리뷰 PR이다. 중간 PR 하나의 머지를 서비스 전체 디자인 완료라고 말하지 않는다. API 추가 요구는 별도 서버 계약 목록으로 공유하며, 동료가 동일 UI를 진행 중이면 claim으로 범위를 먼저 조율한다.

## 완료 판정

- Figma와 같은 393px 너비에서 기본·선택·메뉴 열림·시트 열림·검색 초기/결과·목록·상세·제보를 나란히 확인한다. 로딩·빈 결과·오류·이미지 없음·긴 제목도 확인한다.
- 고정 합성 기사 표본으로 여러 지역 및 기사 수 1/2/5/6/9/10/12를 만들고 지역 수·원 크기·숫자·선택 시트 접근을 검증한다. 이 표본을 운영 데이터처럼 노출하지 않는다.
- 숫자·이미지·상태가 같은 검증 표본에서 서비스 UI의 위치·치수·행간·radius·색·투명도·그림자·폰트 실로드를 확인한다. 지도 타일·기기 목업·원본 기사 내용·로고 및 지역 원의 명시적 변경은 차이 비교에서 따로 표시한다.
- 320px, 393×852, 667×375, 1440×900과 모바일 키보드/안전 영역에서 메뉴·닫기·제출이 가려지지 않고 가로 overflow가 없어야 한다. 데스크톱은 제공된 별도 시안이 없으므로 동일 모바일 화면의 반응형 확장으로 명시한다.
- 기존 검색 저장·페이지별 더 보기/재시도·이미지 fallback·URL 직접 진입·지도 뷰포트 복원·공유 취소/복사·제보 입력/첨부/재시도 키·60초 제한·Suspensive 경계를 유지한다.
- 정확한 행동 테스트와 필요한 시각 검증 사례를 구현 전 제안에 고정한다. 기존 테스트의 의미를 디자인에 맞춰 약화하거나 승인 없이 기대값을 바꾸지 않는다. 불필요한 CSS 문자열 테스트는 추가하지 않는다.
- 전체 vitest, format:check, lint, typecheck, 기본 build와 sobaya gate/review, 화면별 비교 증거, 저널·claim·push를 완료한다. CI 성공만으로 디자인 일치를 선언하지 않는다.
