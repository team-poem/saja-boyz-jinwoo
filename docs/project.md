## 화면 방향

393px 모바일 화면이 중심이다. 전체 지도 위에 반투명 검색창과 필터 칩, 사건 카드 캐러셀, 하단 내비게이션을 띄운다. 흰색·슬레이트 회색과 빨강 강조색, 둥근 모서리, 얕은 그림자를 사용한다. 검색·목록·상세는 같은 밝은 스타일로 이어진다.

| 화면          | Figma 노드       | 경로              |
| ------------- | ---------------- | ----------------- |
| 지도 홈       | 18:2348, 45:3317 | /                 |
| 검색·입력     | 11:1797, 11:1864 | /search           |
| 사건 바텀시트 | 19:2865          | 지도 위 선택 상태 |
| 사건 상세     | 11:2043          | /incidents/[id]   |
| 사건 목록     | 11:2123          | /incidents        |
| 제보          | 11:2221          | /report           |

현재 라우트는 개발 준비 화면이다. Figma 화면 구현, 지도 SDK, 데이터 수집, 제보 저장은 아직 포함하지 않는다. 실제 사건처럼 보이는 샘플 데이터를 서비스에 노출하지 않는다.

## 후속 결정

- 지도 제공자, 키, 사용 조건, 클러스터링 방식 선택.
- Figma에 네이버 뉴스 API 수집 메모가 있다. 수집·중복 제거·위치 추출·갱신 정책을 별도로 설계한다.
- 원문 출처와 발생 시각, 위치 정확도, 상태 변경의 기준을 정한다.
- 제보 저장소, 첨부파일, 검토 및 인증 흐름을 정한다.
- 여러 시안이 공존하므로 화면별 최종 노드를 확인한다. `흉흉`과 `위험추적` 로고명이 혼재하며 현재 기반에는 `흉흉`을 사용한다.
